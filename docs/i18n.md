# Sens in six languages

Sens speaks English, Spanish, French, German, Japanese and Simplified Chinese.
English is the source: every other language translates it, and a key exists
in English first. The installer asks which one the first time; **Settings ›
Language** changes it afterwards, without a restart.

## How copy is written

Each feature keeps its words next to its code, in a `copy.ts` beside the
components that show them:

```ts
import { copy } from "../../shared/i18n";

export const t = copy({
  en: { title: "Capabilities", installed: (count: number) => (count === 1 ? "1 installed" : `${count} installed`) },
  es: { title: "Capacidades", installed: (count: number) => (count === 1 ? "1 instalada" : `${count} instaladas`) },
  fr: { … }, de: { … }, ja: { … }, zh: { … },
});
```

- `copy()` takes all six languages at once. TypeScript refuses a language
  that lacks a key, has one more, or takes other arguments: a missing
  translation does not compile.
- A string that carries a value is a function of it. Plurals, word order and
  particles belong to the language, so the whole sentence is built inside
  each language's function, never glued together outside it.
- Keys name what the words are for (`attach`, `removeFile`), not the words.
- One `copy.ts` per feature folder; a folder that holds several parts with
  words of their own (the chat: its thread, its steps, what you sent) gives
  each one a `<part>.copy.ts`. Words shared across features live in
  `src/shared/copy.ts`; do not import another feature's copy — a component
  that needs another feature's words belongs in that feature.
- The Rust side speaks the same way: see *Messages from Rust* below.

## Reading copy

`t.title` reads the language shown **when it is read**. Changing the language
mounts the interface again, so anything read while rendering follows it.

- Never read copy at module level. A table of labels is a function
  (`const modes = () => [{ id: "plan", label: t.plan }]`), or it keeps ids and
  reads the label where it is drawn.
- Dates, numbers and sizes go through `Intl` with `localeNow()` from
  `shared/i18n`; `shared/format.js` already does.
- Nothing matches on words a person reads. Code compares ids, kinds and
  codes, never a translated sentence (and never a Spanish one from Rust).
- `aria-label` and `title` are copy too.
- Tests run in Spanish (`src/dev/test-setup.ts`), so the Spanish of an
  unchanged screen stays word for word what it was.

## Voice

Plain, short and exact, as `docs/brand/identity.md` asks: sentence case, no
exclamation marks, no filler. Each language reads as if written in it, not
translated into it.

| Language | Address | Notes |
| --- | --- | --- |
| English | you | Sentence case. "Folder", "file". |
| Español | tú | Spain Spanish: "fichero", "ordenador". Keep the existing Spanish copy as it is. |
| Français | vous | Typographic space before `: ; ? !` (` ` or a normal space), `« »` quotes, "fichier", "dossier". |
| Deutsch | du | Short compounds, no anglicisms where German has a word; "Datei", "Ordner". |
| 日本語 | です・ます in sentences; noun phrases for labels and buttons | No spaces between Japanese words; a space around Latin words is optional, be consistent within a string. Use 「」 for quotes. |
| 简体中文 | 你 | Full-width punctuation (，。：？); no space between Chinese and Latin or numbers is fine, be consistent. |

## Messages from Rust

Rust reports what went wrong as sentences a person reads, so it speaks the
chosen language too. The app keeps the choice in `language.json` next to
`look.json`; the installer writes it there first. Code in TypeScript never
compares one of these sentences: when the interface needs to tell one case
from another, Rust gives it a kind or a code, not words.
